# Atlas Validation: The RH Rediscovery Benchmark

**Status:** Draft 0.2 (amended 2026-08-01) · Companion to `atlas.md`.
**Acceptance thesis:** the Atlas is done when, handed the Riemann Hypothesis and a statement-level corpus of the surrounding mathematics — with every known cross-connection *withheld* — it rediscovers the famous approaches to RH from structure alone. Not "produces novel insight": rediscovers, cold, the attack map that took mathematicians 165 years to draw. If it cannot find Hilbert–Pólya when handed both sides, it cannot find anything; if it can, then running the same mechanism where no answer key exists is a justified experiment rather than a hope.

## 1. Ground rules

**Cold start.** The validation corpus contains *ingredients* (statements from each theory, formalized and elaborated) but zero *analogical* cross-theory edges: no lemma citing across clusters, no shared ad-hoc definitions that smuggle a connection, no dictionary rows. One carve-out, stated precisely because it looks like an exception: the classical reformulation `Iff`s of the RH family ("RH ↔ Λ ≤ 0", "RH ↔ the Weil-criterion positivity") *are* corpus inputs — they are published statements, and V6 explicitly validates equivalence-graph *assembly* from them, not discovery. What is withheld is every edge the suite asks the Atlas to *find*: the skeleton-level analogies (V2, V3, V5), the dictionary rows (V1, V4), and the generalization (V7). No withheld edge may be derivable by composing the input `Iff`s alone. The known answer key — which approaches connect which clusters via which skeletons — is maintained as a separate frozen document that the indexing pipeline never reads. Custody (decided 2026-08-01): the key lives *outside this repository* in private storage, referenced from the repo only by content hash — freezing stays auditable without exposure, and repo-working agents (which read everything in a repo) cannot read it. Rediscovery means the Atlas proposes edges present in the answer key without having seen them.

**Development vs. validation targets (amended 2026-08-01).** This document publishes V1–V9's substance (§3), and the agents who build both the corpus and the indexes read this repository — so V1–V9 are **development targets**: legitimate for building against and for regression, incapable of supporting a cold-rediscovery claim. The validation set proper is a list of **held-out targets** that exist only in the private answer key, with the same per-target anatomy (triggering operation, required output, pass bar, T1/T2 tier) and their own negative controls, never described in-repo. *Coverage without leakage:* held-out targets may only reference statements the public §2 cluster specifications already require — the key author verifies this — so cluster-writing agents work from the §2 lists verbatim and need no target knowledge. *Burn rule:* once a held-out target is evaluated (results published in-repo, pass or fail), it becomes a development target; the key must be replenished before the next validation claim. *Honest caveat, recorded:* on a single-machine, agent-implemented project this blinding is procedural — the committed hash proves the key predates the corpus and indexes (temporal auditability), but cannot cryptographically prevent a future session from reading the private file; "implementing sessions do not read the key's location" is part of the protocol, and the key's location is deliberately not recorded anywhere in this repository.

**Answer key v1 frozen 2026-08-01** · sha256: `9d102c8c9b5701ff1cd17ada64b342615e650d329e4733fcee4c59d63fc1a382`

**Leakage controls.** Statement formalizations are hash-frozen before any Atlas run (reusing the agent layer's statement-unchanged machinery). Naming is scrubbed: cluster files use neutral declaration names (`zeroSet_re_eq_half`, not `hilbert_polya_target`), because skeleton matching must fire on structure, not on an agent reading suggestive identifiers — and the Atlas pipeline is symbolic, but validation runs will involve agents, and agents read names. Corpus construction and answer-key construction happen in separate passes with the key written first (so the corpus can't be unconsciously sculpted toward what the index finds easy).

**What counts.** Each target below specifies the triggering operation, the required output, and the pass bar. Full pass = the specified connection appears in the top-k results (k per target) with the correct skeleton or cluster structure. Partial = appears but ranked poorly, or the skeleton is coarser/finer than specified while still capturing the connection. Fail = absent or wrong.

**Honesty tier.** T1 targets are must-pass — they're squarely what the five indexes are built to do, and failure means the design is wrong. T2 are partial-credit — plausible for the mechanism but pushing it. T3 are *declared out of scope with reasons*, listed so that nobody later claims the benchmark was gerrymandered by omission: a validation doc that only contains winnable tests is marketing.

## 2. The validation corpus (a deliverable in itself)

Statement-level formalization only — `sorry`-free *statements*, no proofs required (the Formal Conjectures genre). Language ruling (2026-08-01): validation clusters are written in plain Lean and ported to FH surface syntax opportunistically once M1/M2 land — Atlas validation therefore has zero dependency on FH language milestones. Mathlib already provides the anchor: `RiemannHypothesis` is stated, `riemannZeta` and its zeros exist, and the analytic prerequisites are deep. Clusters to build or import, each a few dozen statements: **Z-arithmetic** (Euclidean division, Bézout, unique factorization, Euler product for ζ — largely in Mathlib); **FF-arithmetic** (the same chain for `Polynomial (ZMod p)`, curve point-counts N_m, the rational zeta shape Z(u), the eigenvalue form N_m = pᵐ + 1 − Σαᵢᵐ, |α| = √p, and the surface-intersection positivity statement that powers RH-for-curves — the Castelnuovo–Severi-inequality shape V3 consumes — mostly to be written); **Spectral** (inner products, self-adjoint operators, spectrum-is-real, eigenvalue bounds — in Mathlib); **Positivity** (quadratic forms, PSD criteria, a statement-level Weil-criterion form "RH ↔ a specific quadratic form ≥ 0 on test functions" — to be written); **Deformation** (the de Bruijn–Newman setup: the heat-flow family Hₜ, Λ, "RH ↔ Λ ≤ 0", "Λ ≥ 0" — to be written); **Counting/error** (PNT with error term, ψ(x) explicit-formula shape "error = Σ over zeros of x^ρ/ρ" — partially in Mathlib post-PNT); **L-family** (Dirichlet L-functions, their Euler products, their RH statements — partially in Mathlib); **Zero-density** (Ingham-shape statements: "#zeros with Re > σ up to height T ≤ T^{f(σ)}" — to be written); **Pair-correlation** (Montgomery's conjecture statement; the GUE pair-correlation density with its explicit 1 − (sin πx/πx)² kernel — to be written); plus the twelve FH corpus groups as background noise/controls. Estimated scope: 150–300 statements, the majority short; the FF-arithmetic and Positivity clusters are the real formalization work.

## 3. Rediscovery targets

*(Per §1's amendment: V1–V9 below are development targets; the validation set proper is held out in the private key.)*

**V1 (T1) — The Euclidean skeleton (warm-up, calibrates the whole pipeline).** Input: Z-arithmetic + FF-arithmetic. Required: `atlas dictionary` assembles the row set {prime ↔ irreducible, |n| ↔ p^deg, gcd ↔ gcd, unique factorization ↔ unique factorization, Euler product ↔ Euler product}, with `atlas home` reporting both factorization theorems' true home as the shared EuclideanDomain-level structure, via the carrier-abstraction + lattice-walk composite of `atlas.md` §1b — these are concrete-instance statements with no class binder to weaken directly (i.e., the dictionary's *explanation* — same generic theorem, two instances — is surfaced, not just the pairing). Pass: complete row set, correct shared home, top-3 ranking per row. This target is where anti-unification, bound-minimization, and dictionary assembly are all exercised on ground truth with a known-perfect answer.

**V2 (T1) — Hilbert–Pólya.** Input: Spectral + the RH cluster. Required: `atlas similar` on the RH statement surfaces spectrum-is-real (self-adjoint ⇒ real eigenvalues) via a shared skeleton of the form "distinguished set of complex numbers ⊆ a real line/axis," and `atlas transport` on the resulting row emits the directed gap: the missing witness is an operator + inner-product space making the zeros a spectrum. Pass: the match in top-5; the transport report names the missing object as an unfilled existential (the benchmark's poetry requirement: the machine must ask for the operator).

**V3 (T1) — Weil positivity / intersection positivity.** Input: Positivity + FF-arithmetic (which contains the surface-intersection positivity statement) + RH cluster. Required: the quadratic-form-nonnegativity skeleton links the Weil-criterion reformulation of RH with the FF-side positivity that proves RH-for-curves; `atlas dictionary` places the row with epistemic tags (FF side proven, Z side open). Pass: row found, tags correct.

**V4 (T1) — The grand dictionary and its missing entries.** Input: everything Z-side and FF-side. Required: `atlas dictionary Z FF` produces the partial functor at theory scale *and* the missing-entry report contains, at minimum: no Z-side match for the Frobenius endomorphism statements, and no Z-side match for the base-field/product-over-base statements (the F₁ hole). Pass: both gaps named in the report; the report distinguishes "unmatched because absent" from "unmatched because low similarity." This is the flagship: the benchmark's answer key here is literally the conversation that started this project, and the Atlas must reproduce its final map — dictionary complete for one curve, broken exactly where two copies are needed.

**V5 (T1) — Zeros control errors (the explicit-formula skeleton).** Input: Counting/error + FF-arithmetic. Required: `atlas similar` links "PNT error = sum over ζ-zeros of x^ρ terms" with "N_m − (pᵐ+1) = −Σ αᵢᵐ" through a shared skeleton "deviation from expected count = signed sum over spectral parameters," and links each side's RH statement to its "square-root error" corollary within-cluster. Pass: cross-link in top-5; both within-cluster links present in the equivalence/consequence structure.

**V6 (T1) — Reformulation cluster assembly (de Bruijn–Newman and friends).** Input: Deformation + Positivity + RH cluster, including the stated `Iff`s. Required: the equivalence graph places RH, "Λ ≤ 0", and the Weil-criterion positivity in one reformulation cluster; querying the cluster returns all faces; the cluster report flags "Λ ≥ 0" as an adjacent *non*-member that sharpens "Λ ≤ 0" to "Λ = 0". Pass: cluster complete, the sharpening surfaced. (This target validates graph assembly rather than discovery — the `Iff`s are inputs — but reformulation retrieval is the single most-used agent query, so it gets a target.)

**V7 (T2) — GRH as anti-unification output.** Input: L-family + RH cluster, *without* a stated GRH. Required: anti-unifying RH-for-ζ with the L-function statements yields the family-parameterized skeleton — i.e., the Atlas *generates* the GRH statement shape as the least general generalization of its instances. Pass: the emitted skeleton is GRH up to renaming. Partial: a coarser family that still parameterizes over the L-function. This is the "generalization for free" mechanism pointed at a case where the generalization is famous.

**V8 (T2) — Pair correlation / GUE.** Input: Pair-correlation cluster. Required: `atlas similar` matches Montgomery's conjectured zero-pair-correlation density with the GUE eigenvalue-pair-correlation density — realistically via near-identical formula subtrees (the shared 1 − (sin πx/πx)² kernel) rather than deep structure. Pass: match found. Honest caveat recorded in the target itself: this validates formula-level matching, not the statistical reasoning that made the connection famous; a pass here is pattern-matching doing pattern-matching's job.

**V9 (T2) — Zero-density as proof-shape retrieval.** Input: Zero-density cluster + proof-shape index over corpus proofs. Required: querying "approaches for statements of shape ∀-elements-satisfy-P" returns the exceptional-set-bounding shape ("bound #violations, shrink the bound") as a distinct strategy from direct proof — the structural signature of the Ingham→Guth–Maynard lineage. Pass: the strategy surfaces as a ranked suggestion. Partial: surfaces only when the query names the exceptional set. This target is deliberately hard: proof-shape indexing is the least-developed index, and V9 failing narrowly is acceptable at v1 (recorded as such now, so a later pass means something).

**V10 (T3, declared out of scope) — with reasons, so the omissions are audited.** *Pretentious number theory*: an alternative proof-method whose statements don't structurally reference zeros at all; rediscovering it requires method-level analogy over a corpus of pretentious-style proofs that won't exist at validation time. *Decoupling/incidence imports*: the Guth–Maynard toolkit transfer is visible only in proof internals of proofs nobody will have formalized. *Berry–Keating xp and quantum chaos*: physics-side heuristics with no formalizable statement cluster. Each is out because the *corpus* can't contain it yet, not because the mechanism is known to fail on it — the distinction matters, and moving any of these to T2 requires only building its cluster, which is the intended growth path of the benchmark.

## 4. Negative controls

Required non-matches, weighted equally with the positives (a matcher that matches everything passes every positive test): corpus Group 12 (verified gcd / termination) must *not* enter the RH cluster's top-20 similar set; a **scrambled dictionary** (V1's rows with FF-side entries randomly permuted) fed to `atlas transport` must produce refutations/failures, not confirmations; `atlas frontier` between two genuinely unrelated small clusters (e.g., the corpus's PMF group vs. Z-arithmetic) must score below every true-positive frontier (the frontier scores computed on the same corpus for the answer key's connected pairs — Spectral↔RH-cluster, Positivity↔FF-arithmetic, Counting/error↔FF-arithmetic — the comparison baseline, since no V-target tests `frontier` positively); and V4's missing-entry report must not "helpfully" match Frobenius to some arbitrary Z-side endomorphism-shaped statement (precision on absences is the report's whole value).

## 5. Scoring and cadence

Suite pass = all T1 full + ≥ half of T2 at partial-or-better + all negative controls clean. (Amended 2026-08-01: that criterion governs the *development* suite. A validation claim additionally requires the held-out suite — all held-out T1 full, ≥ half held-out T2 at partial-or-better, held-out negative controls clean, per the pass bars written inside the key itself — with results published in-repo either way and evaluated targets burned per §1.) Run the suite on every Atlas index change (it doubles as the regression suite); publish per-target results, including failures, in-repo. When the suite passes: the same pipeline, pointed at full Mathlib with no answer key, inherits exactly as much credibility as this benchmark earned — which is the only kind of credibility a relationship-mining system can have.
