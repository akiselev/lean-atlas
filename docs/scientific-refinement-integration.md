# Lean Atlas in the scientific refinement loop

Atlas remains a read-only relation/intelligence engine over exact Lean objects. The
scientific stack adds external artifact links; it does not make Atlas the simulator,
validator, proof checker, or research campaign authority.

## Closed loop

```text
Resolvent model structure
        |
        v
    Lean Atlas
 candidate theorem / transformation / representation
        |
        v
       Lean
 proof / refutation under explicit assumptions
        |
        v
    Resolvent
 checked refinement / generated obligations
```

Atlas proposes and retrieves; Lean establishes formal truth; Resolvent makes checked
mathematics executable; Sinbad performs simulation; Pi Lab decides research/evidence
promotion.

## External artifacts

`atlas::artifact` introduces a small typed relation algebra linking a Lean declaration to a
versioned foreign object:

- Resolvent `ScientificSpec`, refinement receipt, operator or certificate;
- Sinbad result/validation artifact;
- Pi Lab evidence or campaign object;
- another content-addressed scientific system.

Atlas stores the foreign authority, schema, digest and optional locator. It does **not**
parse a foreign JSON object and reinterpret it as a Lean theorem.

The relation meaning remains explicit (`ReifiedAs`, `RefinedInto`, `ImplementedBy`,
`ValidatedBy`, `ObservedBy`, `DerivedArtifact`) and the evidence is separately typed.

A `ReifiedAs` edge cannot be constructed from heuristic, asserted or empirical evidence. It
requires a named Lean theorem or checked certificate. This mirrors the existing Atlas rule
that a structural analogy cannot masquerade as a proved equivalence.

## Evidence boundaries

These statements remain independent:

- **formal truth:** Lean checked a proposition;
- **mathematical reification:** a theorem/checker connects a Lean declaration to Resolvent;
- **numerical validation:** a computation passed a stated test;
- **empirical validation:** an observable/measurement model agreed with data under a
  protocol;
- **novelty/significance:** literature/domain review supports a scientific claim.

Atlas may index all five as separately warranted relations. It must never collapse them into
one edge or score.

## Physics-aware search

The existing roadmap's boundary remains correct: generic Atlas core does not infer physical
adequacy from syntax. Domain plugins may ingest Resolvent metadata (linearity, symmetry,
variational structure, conservation, spaces, etc.) to improve theorem/method retrieval, but
those features are retrieval evidence, not proof that the physical model applies.

## Process Atlas connection

Pi Lab/project laboratories may export typed process events and promoted artifact links for
analysis. Atlas is a mining consumer; it is not the append-only campaign authority and cannot
upgrade an exploratory attempt to established evidence.

This is particularly important for repeated-failure mining: Atlas may discover that several
distant strategies share a mathematical obstruction, but promotion of that obstruction as a
claim still requires the campaign's source/proof/counterexample process.
